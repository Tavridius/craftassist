# Правила составления статей и гайдов

Свод для раздела `/guides`. Пополняется по мере накопления решений.
Технику раздела см. в `backend/app/db/guides.py`, сид — `backend/content/guides/`.

---

## 1. Источники и цитирование

1. **Ники игроков не указываем никогда.** Ссылаемся на форум, чужой опыт,
   жалобы и наблюдения — только обезличенно: «игроки пишут», «в фидбэке жалуются»,
   «один из игроков замерил». Ссылка на тред допустима, ник — нет.
   Причина: чужой ник в индексируемом тексте — персональные данные третьего лица,
   плюс это втягивает сайт в форумные конфликты.
2. Официальных лиц тоже без ников: «разработчики ответили», «комьюнити-менеджер
   уточнил». Роли достаточно.
3. **Разделяем официальное и наблюдаемое.** Всё, что не из патчноута/анонса,
   помечаем словами: «по наблюдениям игроков», «официально не подтверждено».
   Читатель должен видеть, где факт, а где чей-то первый день.
4. **Не выдумываем цифры.** Чего не знаем — про то просто не пишем.
   Отдельного раздела «что пока неизвестно» быть не должно: мелкие пробелы
   (точная минута спавна, число установок, размер выплаты) читателю не важны,
   а перечисление дыр обесценивает остальной текст. Исключение — если незнание
   меняет решение игрока; тогда одна строка по месту, не разделом.
5. Даты и источники в конце не обязательны, но снимок данных (`<p class="gsnap">`)
   у любых цен и таблиц — обязателен.

## 2. Именование

- Игра: **STALZONE**, при первом упоминании и в SEO-полях — с хвостом
  «(Сталкрафт)». Спрос по старому имени всё ещё выше, см. `seo-growth-plan`.
- Фракции по новым именам: **Заря** (бывш. Свобода), **Рубеж** (бывш. Долг),
  **Завет**. Форумный сленг («зорьки») в текст не тащим.
- Локации и предметы — ровно как в игре, с кавычками-ёлочками: «Шайба», «Тесла».

## 3. Тон

- Пишем по делу, без рекламных оборотов и без «дорогой читатель».
- Не пересказываем патчноут абзацами — сжимаем в выводы и таблицы.
- Критику механик передаём как факт наличия критики, а не как свою позицию.
- Мат из цитат вычищаем, смысл сохраняем.

## 4. Структура

- Первый абзац — что это и зачем читать дальше, без предысторий.
- Дальше `<h2>` блоками по одному вопросу. Заголовок формулируем так, как
  человек спросил бы в поиске.
- Самое практичное (что делать, куда идти, сколько стоит) — выше середины.
- Заканчиваем разделом «что ещё неизвестно» либо ссылками на наши инструменты.

## 5. Вёрстка (доступные классы)

Тело гайда — доверенный HTML, рендерится как патчи (`.patch-body`).

| Класс | Назначение |
|---|---|
| `gt-wrap` + `gt` | обёртка и таблица (обязательна обёртка — горизонтальный скролл на мобиле) |
| `gn` + `gi` | имя предмета с иконкой 32×32 внутри ячейки таблицы |
| `gnote tip` / `warn` / `err` + `gnote-t` | врезка с заголовком |
| `gcards` + `gcard` (`--gc` цвет) + `gcard-t` / `gcard-s` | плитки-карточки |
| `gstats` + `gstat` | строка ключевых чисел |
| `gsnap` | подпись «снимок данных на дату» |
| `bad` | красное значение (минусы, штрафы) |

Иконки предметов: `<img class="gi" src="/icons/<категория>/<id>.png" alt="…"
loading="lazy" width="32" height="32">`, ссылка — `<a href="/item/<id>">`.

Своих `<style>`, `<script>`, инлайн-стилей (кроме `--gc`) не добавляем.

## 6. SEO

Мета берутся из `title` и `description` гайда (`routers/pages.py`,
`guide_page`), тело уходит в серверный HTML и индексируется без JS,
слаг попадает в `sitemap.xml` при `published=1`.

- `title` — до ~70 знаков, начинается с сущности, а не с «Гайд по…».
  Шаблон: `<Сущность> в STALZONE: <что внутри через двоеточие>`.
  К титулу страницы движок сам добавит « — STALZONE (Сталкрафт)».
- `description` — 150–200 знаков, перечисляем конкретику (числа, названия),
  внутри один раз «STALZONE (Сталкрафт)».
- `tags` — 3–5 штук, теми словами, которыми ищут.
- `cover` — путь к иконке из `/icons/...`, идёт в og:image и JSON-LD.
- `created_at` — дата в `YYYY-MM-DD`, влияет на `datePublished`.
- Перелинковка обязательна: минимум 2–3 ссылки на наши разделы
  (`/items`, `/item/{id}`, `/market`, `/auction`, `/builds`, `/craft`,
  `/barter`, `/obmen`, `/compare`, `/operations`, `/quests`, `/patches`)
  и на смежные гайды.
- **На `/map` не ссылаемся** — раздел не готов и закрыт `noindex`.
- Заголовки `<h2>` — это семантика для поиска, в них живут запросы
  («сколько стоит», «как фармить», «где найти»).

## 7. Картинки

- Первый источник — **официальные материалы EXBO**: анонс на форуме и та же
  новость в Steam (`store.steampowered.com/feeds/news/app/1818450/`). Там уже
  лежат кадры интерфейса, карт, аномалий и магазинов, ради которых иначе
  пришлось бы заходить в игру.
- Кладём в `frontend/guide-img/`, имя — `<slug-тема>.webp`.
- **Обязательно жмём** через компрессор проекта (`app.services.imgopt.compress`,
  WebP 1280 px, q82): исходники из анонсов весят по 2–3 МБ штука, а вес страницы
  уже один раз стоил нам 53.8% отказов (`AUDIT-METRIKA-2026-07.md`).
- Разметка: `<img src="/guide-img/…" alt="…" loading="lazy" width="…" height="…">`.
  `alt` — осмысленное описание с названием сущности и «STALZONE (Сталкрафт)»,
  это тоже SEO. Размеры проставляем, чтобы не прыгала вёрстка.
- 5–7 иллюстраций на статью достаточно; суммарно держимся в пределах ~400 КБ.

## 8. Актуальность

- У событий с датой окончания в тексте пишем срок явно.
- Цены — только снимком с датой и ссылкой на живой инструмент.
- Если статья вышла в день патча, помечаем, что данные первого дня и часть
  цифр уточним. Возвращаемся и правим.
