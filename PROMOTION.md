# 📈 StalZone Helper — план продвижения и развития

Цель: органический трафик из Яндекса (основной для RU-аудитории) и Google.
Стратегия: сначала техническая индексация → потом выборочные страницы под
реальный спрос → калькуляторы и контент как новые точки входа. Массовых
шаблонных лендов не делаем.

**Семантика — ДВА названия игры:** игра недавно переименована Stalcraft → STALZONE,
основной объём запросов пока на старом имени («сталкрафт», «stalcraft»). Все
тайтлы/тексты — с обоими названиями («STALZONE (ранее Stalcraft)»), в Вордстате
проверять оба. По мере миграции аудитории на новое имя — следить в Вебмастере.

**Конкуренты (разведка 11.07.2026):** ниша инструментов НЕ пустая —
multitoolsx.live (StalZone Multitool: wiki, аукцион, есть калькулятор крафта),
stalcraft.info (аналитика аука + справочник крафта), staldata.org,
scmarket-tracker.com, schistory.xyz, scpmodel.ru. Но запрос «что выгодно
крафтить» никем из инструментов не занят (в выдаче форумы и LJ-статьи) —
это наша главная возможность (готовый rankings). Дифференциация: рекурсивное
дерево крафта с вердиктом на каждом узле + авто-рейтинги выгоды.

## Этап 1 — Индексируемые страницы: выборочно, под реальный спрос

### ✅ Сделано (13 июля 2026, НА ПРОДЕ)
- History API-роутинг: реальные пути `/item/{id}`, `/auction`, `/artefact/{id}`,
  `/builds`, `/profile`, `/search`, `/vygodno-kraftit` вместо `#hash`. Старые
  hash-ссылки (`#item=…` и т.п.) разово мигрируют в новый путь при загрузке —
  расшаренное в комьюнити не ломается.
- SSR-лайт (`backend/app/routers/pages.py`): сервер отдаёт `index.html` с
  подставленными title/description/canonical/og под каждый URL (карточка предмета
  тянет имя + цену). Разделы noindex: `/profile`, `/search`.
- Посадочная **«Что выгодно крафтить»** — `/vygodno-kraftit` (свой тайтл + H2,
  контент = живой rankings). Внутренняя перелинковка в футере.
- Динамический `/sitemap.xml`: только осмысленные посадочные (/, лендинг,
  /auction, /builds) — без тысяч карточек.
- `/index.html` → 301 на `/`; `/mvp/*` по-прежнему 301 (nginx).

### Осталось
- **Product/Offer JSON-LD** на карточках предметов (сейчас общий WebApplication).
- Выборочно добавлять топ-предметы в sitemap — по факту появления показов
  в Вебмастере (не пачкой).

**Историческая справка (решено выше):** роутинг был на `location.hash`
(`#item=okp24`) — поисковики не индексировали фрагменты.

**Чего НЕ делаем:** не выкатываем все ~2300 карточек в индекс. Спрос по названиям
предметов сконцентрирован в верхушке (топовое оружие/броня/арты), по остальному —
ноль показов. А тысячи шаблонных страниц на свежем домене без ссылочной массы —
прямой путь под фильтры (Яндекс: МПК/дорвеи, Google: scaled content abuse),
которые топят весь домен, а не только эти страницы.

**Что делаем:**
1. History API + реальные пути `/item/{id}` (fallback на hash) — нужно в любом
   случае: нормальные ссылки с og-превью (название + цена + вердикт) для шаринга
   в Discord/VK. Для игрового сервиса шаринг в комьюнити — канал жирнее SEO.
2. FastAPI по `GET /item/{id}` отдаёт `index.html` с подставленными title/
   description/canonical конкретного предмета — механика та же «SSR-лайт»,
   вопрос только в том, ЧТО пускаем в индекс.
3. **Сначала спрос, потом страницы:** проверить в Яндекс.Вордстате реальные
   запросы («<предмет> крафт», «<предмет> цена», «что выгодно крафтить»,
   категории). Список живых запросов = список посадочных.
4. В sitemap и индекс — только подтверждённое:
   - **«Что выгодно крафтить сегодня»** из готового `rankings` — главная
     посадочная: спрос точно есть, данные живые, у вики-сайтов такого нет;
   - топ-50–100 предметов по популярности (счётчик уже есть) — с ценой,
     вердиктом и `Product`+`Offer` разметкой;
   - категорийные страницы («крафт брони», «крафт оружия») — если Вордстат
     подтвердит спрос.
5. Остальные карточки живут по реальным URL для шаринга, но в sitemap не входят.
   Расширять покрытие по факту: появились показы в Вебмастере → добавить в sitemap.

Наш угол против вики: они отвечают «что это за предмет», мы — «сколько стоит и
выгодно ли крафтить» (живые цены). На запросах с экономическим интентом
конкуренции нет.

## Этап 2 — Калькуляторы (новые посадочные под кластеры запросов)

Каждый калькулятор = отдельный URL со своим тайтлом. Идеи по убыванию ценности:

| Калькулятор | Запросы | Данные уже есть? |
|---|---|---|
| **Калькулятор сборок** (броня + артефакты + оружие: суммарные статы и полная стоимость сборки по ценам аука) | «stalzone сборка», «билд под X» | частично (цены есть, статы предметов — в listing.json) |
| **Стоимость прокачки убежища** (сколько стоит верстак N-го уровня в материалах по текущим ценам) | «убежище прокачка стоимость» | да (hideout.py) |
| **Калькулятор фарм-часа** (что выгоднее крафтить на продажу; уже есть rankings — вывести отдельной страницей) | «что крафтить на продажу» | да (rankings) |
| **Калькулятор бартеров** (бартер vs аукцион) | «бартер выгода» | да — `ru/barter_recipes.json` в stalzone-database (1.5МБ, лоадер его сейчас не берёт) |

## Этап 3 — Контент

Приоритет — **автогенерируемый** контент из живых данных (уникальный и всегда свежий,
ноль ручного труда):
- «Топ-10 выгодных крафтов недели» — страница из готового `rankings`, обновляется сама.
- «Биржа ингредиентов» (график цен уже есть) — вынести на отдельный URL с историей.

Ручные статьи `/guides/` — когда появится трафик и понимание запросов из Вебмастера:
- гайды «как скрафтить X с нуля», «экономика крафта для новичка»;
- обзоры изменений цен после патчей (инфоповоды — быстрые переходы).

## Техдолг под SEO (по мере сил)

- Self-host шрифта JetBrains Mono (Google Fonts блокирует рендер, из РФ бывает медленно) → Core Web Vitals.
- og:image 1200×630 (баннер в стиле терминала) — для репостов в соцсети/мессенджеры.
- Динамический `document.title` при открытии карточки (UX + история браузера).
- Корректный 404 для несуществующих путей.
